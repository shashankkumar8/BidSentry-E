# Synthesis of the supplied Exact Copies bundle and project history

This synthesis turns the supplied references into a repeatable build process. The original four reference files are archived unchanged as `references/Exact_Copies_Bundle.zip`.

## A. How to build a strong hackathon solution

1. Decode the official brief, eligibility, timeline and exact judging rubric before coding.
2. Research a real user and the moment of pain. Keep measured facts separate from assumptions.
3. Compare current alternatives; avoid claiming a generic feature is unique just because your UI is new.
4. Form several solution hypotheses, score them on user pain, differentiation, feasibility, measurable impact and evidence risk.
5. Choose one narrow job and freeze `SPEC.md` with explicit non-goals and acceptance tests.
6. Implement one end-to-end vertical slice: input → source/retrieval → transformation → stored/returned result → visible UI → failure handling → tests.
7. Test edge cases and malicious/ambiguous inputs, missing profile facts, negative wording, empty sources, stale pages, auth failures and API schema mismatches.
8. Prepare a proof-led story: problem, user, solution, architecture, what works, limitations, validation metrics, roadmap.
9. Run a fresh-install audit; remove keys/cache/runtime state; verify ZIP, visuals, docs and links.
10. Rehearse judging questions and report only results actually measured.

## B. How this applies to BidSentry-E

- **User moment:** decide what to verify before investing more time in a tender.
- **Wedge:** source-linked clause ledger, conservative comparison, visible Unknown state and exact-page recheck.
- **AI role:** TF-IDF relevance ranker plus TinyFish structured inspection for dynamic pages. It is not a trained eligibility predictor.
- **Trust rule:** snippets are not evidence; Agent quotes need an independent Fetch match; human review remains required.
- **Failure modes:** no fake fallback on live errors, no guessed exemptions, no universal experience formulas, no fake telemetry, no fabricated ROI/margins.
- **Validation plan:** live integration smoke test, labelled 25–50 tender sample, dual review, reviewer interviews and measured UX/evidence metrics.
